# 标准属性

字段名只有一个意思，换地方也不换。下面按用途分组，一条一句。

标记写在名字后面：确认是我定过的，怀疑是照道理推出来、还没定过的。现在确认九条，其余十条怀疑——标了怀疑不等于错，只说明还没拿它当规矩用。

本页自 qtfounder 归位工具的案例集迁入：该工具淘汰时，已确认的标准字段随迁至此，未确认的公理、关系与模型不迁，留痕在 quanttide-gallery-of-founder 仓的 git 历史。

## 标识属性

- id（确认）：全局唯一键，用 uuid；改名不动它，引用认它。
- name（确认）：机器可读标识，小写、连字符、英文；同一类里不重复，格、家族、公理都用它。
- label（确认）：给人看的称呼，可中文、可改，不进引用。
- title（确认）：标题，写在正文第一行；日志的标题就是日期。

## 分类属性

- category（确认）：用户自定义的类别，谁用谁定，可增可删。
- type（确认）：系统定义的类型，由本体写定，用户不改；格用 `family` 承载它，取值陈述型或程序型。

## 位置属性

- path（确认）：存在哪，写到目录或文件。

## 状态属性

- status（确认）：可信到什么程度，公理写 confirmed 或 suspected。

## 内容属性

- description（确认）：一段话说清它是什么，管到哪，收什么不收什么。
- skeleton（怀疑）：通常要交代的内容，不排顺序。
- cues（怀疑）：用来认出它的词。
- why（怀疑）：当初为什么这么定，写代价，不写好处。

## 关系属性

- from（怀疑）：起点。
- to（怀疑）：终点。
- pair（怀疑）：成对出现的两个对象。
- ask（怀疑）：把 pair 分开问的那一句。
- require_any（怀疑）：出现其中任意一个才连上。
- lack_any（怀疑）：出现其中任意一个就不连。
- reason（怀疑）：这条关系成立的理由。

## 已确认公理

归位工具留下的九条公理里唯一确认的一条，随本页迁入：

### template-scope（确认）

有固定结构才有模板；结构随内容走的不设固定写法。手册、规格与按日期落的日志结构固定，可以有模板。

代价：结构不固定还套模板，等于让模板替作者删内容。

判例：给洞察定章节。

现象：写一篇洞察，先立「背景与问题、判断、机制、边界、结论」五段，段段齐全，读起来整齐。

错法：把别人文章的结构当成体裁本身。模板越细，正文越像填表，作者想说的东西反而没处放。

正法：洞察不排章节、不写空话；手册与规格结构固定，照模板写；日志的输入是每天发生的事，固定日期就够，其余不排。一篇洞察成不成立，看它的结论能不能被推翻，不看它有没有五段。
